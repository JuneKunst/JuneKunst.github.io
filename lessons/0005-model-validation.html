공유한 글에서 확인한 작성 범위

원문은 로봇 설정·함수 작성·파일 검사·변환·상태 기록을 연결하는 실습입니다. 기존 URDF가 있으면 생성 단계를 반복하지 않고 검사부터 진행할 수 있습니다. 작성 대상은 robot.json, practice_tasks.py의 세 함수, 생성 코드 이해, import_isaac62.py의 경로·베이스 설정, 실제 상태 읽기를 연결할 joint_log.py입니다. 제공 답안 테스트와 본인 구현·물리 시험의 완료를 구분합니다. 글의 변환 코드는 Sim 6.2 기준입니다. ZIP은 링크 본문에서 직접 내려받을 수 있는 주소가 확인되지 않아 이번에는 해당 파일을 실행·수정하지 않았습니다.

MuJoCo가 URDF를 읽을 수 있다고 해서 모든 URDF 확장·USD 기능·드라이브 설정을 자동으로 같은 의미로 보존하는 것은 아닙니다. 변환은 입력을 다른 모델 표현으로 해석하는 단계입니다. 단순 재저장·정적 검사·실제 동역학 시험을 나누어 봅니다.

버전별 실행 위치

기존 학습 페이지의 Sim 6.1 실습과 이번 글의 6.2 importer 예시는 별도 경로입니다. 일반 Python 도구, Isaac의 Script Editor/내장 Python, MuJoCo Python 환경에서 실행하는 코드와 패키지를 구분해 기록합니다. import 성공만으로 해당 시뮬레이터에서 로봇이 동작한 것은 아닙니다.

실제 6.2 설치본의 importer API와 실행 예제를 확인한 뒤 베이스 설정을 고릅니다. 이동 베이스는 자유 이동이 필요하고, 바닥 고정 시험대는 고정이 필요할 수 있습니다. 링크·관절을 합치는 옵션, 시각 메시를 합치는 옵션, 자기 충돌 옵션도 각각 따로 검토합니다.

공식 6.2 API에서 fix_base=False는 Mobile, True는 Fixed, None은 Source입니다. merge_mesh는 rigid body 안의 시각 메시 결합이고, merge_fixed_joints는 별도의 관절 결합 설정입니다. MuJoCo는 URDF를 mjSpec으로 읽고 mjModel로 컴파일할 수 있으며 MJCF 파일 저장은 선택 사항입니다.

단위가 맞아야 수치가 의미를 갖는다

m = mm / 1000, rad = degree × π / 180. 파일의 단위 표기와 실제 숫자가 일치하는지 확인합니다. 회전 속도는 rad/s, 직선 속도는 m/s이며 힘과 토크도 N·N·m으로 구분합니다.

균질 상자의 중심 관성 · 계산 예제

Ixx = m(y² + z²)/12
Iyy = m(x² + z²)/12
Izz = m(x² + y²)/12

단위는 kg·m²입니다. 이 계산은 균질한 상자·질량중심·변과 나란한 축을 가정합니다. 실제 CAD 링크나 내부가 빈 구조의 관성을 이 값으로 자동 대체하지 않습니다. 링크 원점과 질량중심이 다르면 inertial frame의 위치·회전과 기준점 변환도 함께 검토합니다.

어제의 도메인 랜덤화와 연결

질량만 바꾸면서 관성·형상을 독립적으로 아무 값으로 바꾸면 물리적으로 불가능한 조합이 생길 수 있습니다. 먼저 명목 모델의 측정·계산 근거를 정리하고, 실제 불확실성에 해당하는 범위를 설정합니다. 자세 변화에 따른 좌표 표현 변경과 물체 자체의 관성 변화도 구분합니다.

이름·좌표·배열 인덱스는 별개다

정책이 출력한 목표와 실제 관절 상태를 비교하려면 어떤 관절인가, 어느 frame인가, 단위가 무엇인가를 먼저 연결해야 합니다. 숫자 인덱스 0이 항상 같은 관절이라고 가정하지 않습니다.

기록 항목적을 내용
모델 이름 대응원본 joint 이름 → 목표 도구의 joint/dof 이름·ID
기하 대응부모/자식, 영점 pose, 축 방향·양의 회전, 한계
상태 대응position/velocity 주소·차원·단위, 센서/추정 여부
명령 대응position·velocity·effort 중 종류, 스케일·드라이브·포화

MuJoCo에서 qpos와 qvel의 길이가 다를 수 있다

jnt_qposadr는 해당 관절 position 상태가 시작되는 주소이고, jnt_dofadr는 velocity 쪽 주소입니다. Quaternion으로 자세를 표현하는 관절은 position 좌표 수와 속도 자유도 수가 다릅니다. 관절 ID를 두 배열의 직접 인덱스로 재사용하지 않습니다.

Isaac articulation의 DOF 인덱스와 단위도 해당 런타임 API에서 확인합니다. USD 속성·모델 파일의 각도 단위와 런타임 상태 단위를 이름만 보고 같다고 가정하지 않습니다.

한 관절을 검증하는 작은 시험

다른 조건을 고정하고 작은 양수 목표를 보낸 뒤 축 방향·측정된 변화·범위·정착을 봅니다. 원점, 부모/자식 연결, 축, 명령 부호, 메시 배치 문제가 서로 다른 원인인지 확인합니다. 화면 외형의 일치와 물리적 추종의 일치는 별도입니다.

4 / 5 · 이전 복습: 물리 step·평가 증거

최고속도는 기록한 샘플에서만 알 수 있다

실제 시험에서는 엔진 물리 step 직후의 시뮬레이션 시간·관절 상태를 연결해 기록합니다. 화면 캡처 주기나 벽시계 시간으로만 샘플링하면 중간 동작을 놓칠 수 있습니다. 아래 도구는 붙여 넣은 2열 숫자 텍스트만 검사하는 학습 예제입니다. 실제 엔진과 연결하지 않습니다.

검사 범위: 헤더·2열 형식, 비어 있지 않은 데이터, 유한한 수치, 양의 정수 예상 행 수, 0 이상·엄격히 증가하는 시간, 행 수 일치, 모든 |dq| ≤ 제한. 제한과 같은 값은 통과합니다. 빈 칸은 0으로 취급하지 않습니다. 따옴표·필드 내 쉼표를 포함하는 일반 CSV는 지원하지 않습니다.

샘플 조건 충족 ≠ 전체 물리 시험 합격

충돌·전복·위치 오차·누락된 엔진 step·관절 매핑 오류·샘플 사이 최고값은 이 도구가 확인하지 못합니다. 예상 행 수를 채웠더라도 실제 물리 step과 1:1 연결됐다는 별도 근거가 필요합니다. 통과시키기 위해 결과를 본 뒤 제한값을 바꾸지 않습니다.
