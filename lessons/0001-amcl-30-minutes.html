AMCL: 30분 동안 한 흐름으로 이해하기

저장된 지도에서 여러 위치·방향 가설을 유지하고, 이동과 센서 관측으로 가설의 비중을 갱신하는 위치 추정 방법.

목표는 예측·관측 갱신·재표본화·적응·TF를 내 말로 설명하는 것입니다. 구현 전체의 숙달을 시간만으로 보장하지 않습니다. 30분 타이머를 켜고 각 구간의 질문에 직접 답하세요.

한 장 복습표 · 워크벤치 · Nav2·AMCL 메뉴

0–4분 · 이전 개념 두 개

지도와 odom은 역할이 다르다

지도는 공간의 구조를 나타냅니다. odom은 연속적인 상대 이동을 나타내지만 오차가 누적될 수 있습니다. SLAM은 지도와 위치를 함께 추정하고 AMCL은 이미 있는 지도에서 위치를 찾습니다.

바퀴는 1 m 전진했다고 보고했지만 미끄러져 실제로는 덜 갔을 수 있습니다. 지도와 레이저 관측의 일치도가 그 위치 판단을 보완합니다.

저장 지도 + 이동 정보 + 레이저 → AMCL → 위치·방향 추정

생각하기: 지도가 있는데 AMCL이 왜 필요할까요?

설명 예시

지도는 공간을 알려주지만 현재 로봇이 그 지도에서 어디에 있는지까지 자동으로 알려주지 않기 때문입니다.

공식 Mapping and Localization
4–8분 · 입자 하나의 의미

여러 위치·방향 가설을 함께 유지한다

입자 하나는 로봇의 상태 (x,y,θ)에 대한 가설입니다. 같은 위치라도 바라보는 방향이 다르면 다른 가설입니다. 각 가설에는 관측에 얼마나 맞는지를 나타내는 가중치가 있습니다.

비슷한 복도가 두 곳이라면 A에 있을 가설과 B에 있을 가설을 함께 유지할 수 있습니다. 입자 구름은 여러 실제 로봇을 뜻하지 않습니다.

생각하기: 입자가 모였다면 정답이 보장될까요?

설명 예시

아닙니다. 필터가 한 가설에 집중했다는 뜻입니다. 잘못된 지도·센서 TF·초기화·반복 구조 때문에 틀린 위치에 모일 수 있습니다.

8–16분 · 숫자 예제 한 바퀴

예측 → 관측 갱신 → 재표본화

길이 6 m인 복도에서 x 위치만 추정합니다. 실제 AMCL의 y·θ·다중 광선 처리를 생략한 학습용 예입니다.

가설x [m]비중 / 개수

① 예측: 이전 가설이 0.5·2.5·4.5 m이고 odom 이동이 +0.5 m면, 잡음을 생략한 예측은 1·3·5 m입니다. 실제로는 이동 잡음을 반영합니다. 이동 보고를 반영하는 것이며 실제 위치를 확정한 것은 아닙니다.

② 관측 갱신: 오른쪽 벽 x=6 m까지 예상 거리는 가설별로 5·3·1 m입니다. 센서가 1 m를 관측하면 C가 잘 맞습니다. 학습용 정규화 가중치를 0.05·0.15·0.80으로 가정합니다. 실제 센서 모델로 계산한 값이나 실제 정답 확률 보장은 아닙니다.

실제 likelihood_field 모델은 가설별로 레이저 끝점을 지도에 놓고 가까운 장애물까지 거리로 적합성을 평가합니다. 모르는 실제 위치와 비교하는 기능이 아닙니다.

③ 재표본화: 새 입자 20개에서 A 1개·B 3개·C 16개가 나오는 집합을 생각할 수 있습니다. 일반적인 무작위 추출에서 개수가 항상 정확히 이렇다는 뜻은 아닙니다. 새 개별 입자들을 균일 가중치로 두어도 C 위치에 많이 모여 있으므로 C의 비중이 큽니다.

관측이 잘 맞는 가설이 다음 집합에 더 많이 남는 것이 핵심입니다. 새 센서 정보를 추가하거나 정답을 보장하는 과정은 아닙니다.

생각하기: 관측 거리가 5 m였다면 어느 가설이 유리할까요?

설명 예시

A입니다. x=1 m에서 오른쪽 벽 x=6 m까지 거리가 5 m이기 때문입니다.

실제 Nav2는 입자 군집을 구분해 대표 자세를 정합니다. 모든 입자의 단순 전체 평균만 출력한다고 외우지 않습니다.

16–20분 · Adaptive

분포를 표현할 입자 수를 조절한다

입자가 적으면 중요한 가설을 놓칠 수 있고, 무조건 많으면 계산 부담이 커집니다. KLD-sampling은 표본으로 분포를 근사하는 오차를 기준으로 필요한 표본 수를 조절합니다.

직관적으로 여러 위치·방향 구간에 퍼진 분포에는 더 많은 입자가 필요할 수 있고, 집중된 분포는 적은 입자로 표현할 수 있습니다. 실제 개수는 차지한 상태 구간·오차 설정·최소/최대 입자 수 등에 의해 결정됩니다.

생각하기: 입자를 늘리면 틀린 센서 TF도 해결될까요?

설명 예시

아닙니다. 틀린 관측 해석을 더 많은 가설로 계산할 수 있습니다. 입력·TF·시간을 먼저 점검합니다.

Dieter Fox, KLD-Sampling, 2001
20–24분 · TF와 연결

전역 보정과 연속 이동

map → odom: 저장 지도 주행에서 AMCL의 전역 보정
odom → base: odometry 측의 연속 이동
base → sensor: 센서 장착 변환

회전을 무시한 예에서 odom 기준 몸체가 2.3 m, 지도 기준 위치 추정이 2.0 m라면 map→odom 보정은 −0.3 m입니다. −0.3+2.3=2.0입니다. 실제 TF는 회전도 포함합니다.

Nav2 AMCL은 odom→base TF에서 이동 변화를 얻습니다. /odom 토픽 이름만 있다고 입력 조건이 충족되는 것은 아닙니다. scan의 관측 시각과 센서 TF도 필요합니다. frame 이름과 발행 옵션은 설정 가능합니다.

생각하기: AMCL과 Cartographer가 같은 map→odom을 동시에 발행해도 될까요?

설명 예시

같은 TF 변의 발행 책임을 중복시키지 않습니다. 저장 지도 AMCL 모드로 전환할 때 SLAM 측의 같은 TF 발행을 정리합니다.

24–27분 · 파라미터 네 묶음

숫자 암기보다 의미

  • 입자 수: min_particles / max_particles는 적응 표본 수의 하한·상한입니다.
  • 이동 잡음: 차동 모델 alpha1–4는 회전·이동 보고를 얼마나 불확실하게 모델링할지 나타냅니다.
  • 관측 오차: sigma_hit는 거리 오차 모델 폭입니다. 너무 좁으면 작은 불일치에 민감할 수 있습니다.
  • 갱신: update_min_d / update_min_a는 이동·회전 기준이며 m와 rad를 구분합니다.

설치 버전과 운동 모델에 맞춰 확인합니다. 입력·지도·초기 위치·TF·시간 → 모델·파라미터 → 계산량 순서로 점검합니다.

27–30분 · 자료를 가리고 설명

여섯 질문

  1. AMCL의 추정 상태와 필요한 지도는 무엇인가요?
  2. 예측·관측 갱신·재표본화를 한 문장씩 설명하세요.
  3. 벽 x=6 m, 관측 거리 2 m이면 유리한 x 가설은 무엇인가요?
  4. Adaptive는 무엇을 어떤 직관으로 조절하나요?
  5. 입자 집중이 정답 보장이 아닌 이유는 무엇인가요?
  6. 회전할 때 scan이 벽에서 벗어나면 입자 수보다 먼저 무엇을 확인하나요?
먼저 답한 뒤 확인
  1. 저장된 2D 지도에서 (x,y,θ)를 추정합니다.
  2. 이동으로 가설을 옮기고, 관측 일치도로 가중치를 바꾸고, 비중에 따라 다음 입자를 뽑습니다.
  3. 이 1D 예에서는 x=4 m입니다. 6−4=2입니다.
  4. 표본 근사 오차·분포가 차지한 구간과 최소/최대 설정 등에 따라 입자 수를 조절합니다.
  5. 지도·TF·초기화·반복 구조 때문에 오수렴할 수 있습니다.
  6. 지도·초기 위치·센서 TF·timestamp/clock·odom 방향과 이동 모델입니다.

멈칫한 질문 하나만 다시 복습하세요. 답을 읽은 것과 직접 설명한 것은 다릅니다. 에이전트에게 답이나 헷갈린 구간 번호를 보내면 연결부터 다시 확인할 수 있습니다.
