Isaac Sim에서 자연어로 촬영·전진·후진하기

한국어 요청이 로봇 동작으로 이어지는 과정을 Isaac Sim에서 확인합니다. Qwen은 문장을 구조화하고, SmolVLM2는 카메라 영상과 거리 정보를 바탕으로 촬영 여부를 고릅니다. 이동은 별도의 제어기가 수행하고, 시뮬레이터의 차체 위치로 결과를 검증합니다.

  1. 자연어에서 동작까지
  2. GPU PC와 모델 준비
  3. GUI 장면 실행과 명령 입력
  4. 촬영 판단과 LiDAR 거리
  5. 전진·후진과 실제 이동 거리
  6. 문제 확인 순서

1. 자연어에서 동작까지

단계역할
의도 해석Ollama의 Qwen이 한국어 문장을 intent와 meters로 변환합니다. 예를 들어 “뒤로 10센티미터”는 reverse와 양수 0.1로 표현합니다.
입력 검증실행기가 작업 종류와 거리를 검증합니다. 거리는 미터로 통일하고, 전진·후진의 방향은 intent로 구분합니다.
센서와 제어촬영은 카메라와 LiDAR를 사용합니다. 이동은 Isaac Sim에 바퀴 목표 속도를 보내고, 차체의 실제 위치 변화를 확인합니다.
결과 기록request.json에는 해석 결과를, outcome.json에는 촬영 여부나 실제 이동 거리를 저장합니다. 촬영을 선택하면 photo.png가 생성됩니다.

2. GPU PC와 모델 준비

아래는 waffle-mpx-lyrical의 13강을 사용하는 예시입니다. 프로젝트를 빌드한 ROS 2 환경과 Python ABI가 맞는 Isaac Sim 6.1 환경, PyTorch와 CUDA를 사용할 수 있는 Isaac Lab 환경, 실행 중인 Ollama 서버가 필요합니다. 환경 경로는 설치 위치에 맞게 바꿉니다.

cd ~/waffle-mpx-lyrical
LAB=~/IsaacLab/.venv/bin/python
ollama pull qwen2.5:1.5b
uv pip install --python "$LAB" -r learning/requirements.txt
"$LAB" -c 'import torch; print(torch.__version__, torch.cuda.is_available())'
"$LAB" -c "from huggingface_hub import snapshot_download; print(snapshot_download(
  'HuggingFaceTB/SmolVLM2-500M-Video-Instruct',
  revision='4cde9d208e19519c36917aa170fffc7e381aa0ad',
  ignore_patterns=['onnx/*']))"
(cd learning/checkpoints && sha256sum -c SHA256SUMS)

No module named pip가 나오는 uv 환경에서도 uv pip install --python으로 대상 환경에 직접 설치할 수 있습니다. 이 실습은 PyTorch 가중치를 사용하므로 ONNX 변환본은 생략할 수 있습니다. SmolVLM2 고정 리비전

3. GUI 장면 실행과 명령 입력

터미널 A에서 아래 명령으로 Isaac Sim 창을 엽니다. ROS_DOMAIN_ID는 비어 있는 번호를 골라 두 터미널에 동일하게 적용합니다. LOCALHOST 설정은 이 시뮬레이션의 ROS 통신을 같은 PC 안으로 제한합니다.

cd ~/waffle-mpx-lyrical
source /opt/ros/lyrical/setup.bash
source install/local_setup.bash
unset ROS_LOCALHOST_ONLY ROS_STATIC_PEERS
export ROS_DOMAIN_ID=88 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
SIM=~/isaacsim6_venv/bin/python
mkdir -p simulation
python3 tools/export_urdf.py simulation/waffle.urdf &&
  "$SIM" sim/scene.py simulation/waffle.urdf --output simulation

Isaac Sim의 Python에서 rclpy를 불러올 수 있는지 먼저 확인합니다. 배포판과 Python 버전이 맞는 환경에서 ROS 경로를 불러오면 됩니다. 별도 경로에 빌드했다면 해당 install/local_setup.bash를 지정합니다. 창을 표시하려면 --headless를 사용하지 않습니다.

장면을 켜 둔 채 터미널 B에서 명령을 실행합니다. 결과 경로는 실행마다 새 이름을 사용합니다.

cd ~/waffle-mpx-lyrical
source /opt/ros/lyrical/setup.bash
unset ROS_LOCALHOST_ONLY ROS_STATIC_PEERS
export ROS_DOMAIN_ID=88 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
export ISAAC_LAB_PYTHON=~/IsaacLab/.venv/bin/python
ros2 topic list
python3 lessons/13-react/natural_command.py \
  --output "$HOME/waffle-runs/lesson13-$(date +%Y%m%d-%H%M%S)"

자연어 명령 >에 “1.5미터 안에 물체가 있으면 사진을 찍어 줘”, “차체를 앞으로 10센티미터 전진해 줘”, “차체를 뒤로 10센티미터 후진해 줘” 중 한 문장을 입력합니다. 후진과 차체 위치 검증은 아래 설명대로 확장한 실행기에서 사용할 수 있습니다.

4. 촬영 판단과 LiDAR 거리

실행기는 /camera/color/image_raw와 /scan에서 타임스탬프가 가까운 메시지 두 건을 기다립니다. 카메라 이미지와 LiDAR의 최단 유효 거리를 SmolVLM2에 넘기고, 거리가 한계 안이며 모델의 Yes 점수가 더 높으면 사진을 저장합니다.

예시 장면에서는 최단 거리 0.856m를 읽어 1.5m 조건을 통과했습니다. 이 거리에는 LiDAR의 전체 스캔에서 반사된 벽이나 장애물도 포함될 수 있어요. 카메라 정면에 특정 물체가 있는지 확인하려면 카메라와 겹치는 각도 범위로 스캔을 좁히고, 검출한 대상과 거리를 대응시키는 과정이 필요합니다.

5. 전진·후진과 실제 이동 거리

/isaac/wheel_commands로 양쪽 바퀴 속도를 보냅니다. 전진은 양수, 후진은 음수 속도를 사용하고, 이 실습에서는 명령당 이동 거리를 15cm로 제한합니다. 시뮬레이터의 /isaac/joint_states는 바퀴 회전을, 추가한 /isaac/base_pose는 물리 엔진이 계산한 차체의 월드 위치와 방향을 제공합니다.

이동 결과는 base_forward_m으로 확인합니다. 시작 위치에서 현재 위치까지의 변위를 시작 방향에 투영한 값이라 전진이 양수이고 후진은 음수입니다. 바퀴 엔코더의 환산값도 함께 기록하면 바퀴는 회전했는데 차체는 충분히 이동하지 않는 경우를 찾을 수 있습니다.

속도는 출발 직후 점진적으로 높이고 목표에 가까워지면 낮춥니다. 이번 설정은 바퀴 목표 속도를 최대 4rad/s로 제한했습니다. 속도를 바로 크게 주었을 때는 바퀴가 회전해도 차체가 목표 거리에 못 미쳤습니다. 가속과 감속을 적용한 뒤 10cm 요청에 대해 전진과 후진 모두 차체 기준 약 10.01cm를 확인했습니다.

6. 문제 확인 순서

Qwen 응답이 없거나 모델을 찾지 못함
ollama list에서 모델 이름을 확인합니다. 시뮬레이션 없이도 interpret()만 호출해 해석을 확인할 수 있습니다.
카메라와 LiDAR 샘플을 기다리다 시간 초과
Isaac Sim 창에서 장면이 재생 중인지 확인하고, 두 터미널의 도메인과 검색 범위를 맞춥니다. /scan과 /camera/color/image_raw에 발행자가 있는지 확인합니다.
바퀴는 돌지만 차체가 움직이지 않음
/isaac/base_pose의 실제 차체 위치, 바퀴의 가속, 바닥 접촉, 주변 장애물을 확인합니다. 새 토픽이 보이지 않으면 수정한 브리지로 장면을 다시 시작합니다.
촬영 장면과 팔 집기 실습을 전환
집기·놓기는 작업대와 블록이 있는 별도 Isaac Sim 장면을 실행합니다. 기본 촬영 장면을 먼저 종료해 GPU 메모리를 확보하고, 생성된 scene.usda를 --scene 인수에 넘깁니다.
