skill과 동작 흐름

주사위 미션을 진행하는 mission_manager와 skill을 실행하는 coordinator의 흐름입니다. 기준은 develop에 올라간 PR #47 · #48 · #49이고, 2026-11-02 기준 머지 전입니다. 실기·시뮬레이터에서 미션을 돌려 본 적은 아직 없습니다.

1. 구조 — 누가 무엇을 하나

skill 하나 = coordinator가 실행하는 SubGoal 한 단계입니다. 단계 순서는 계획을 보내는 쪽(① mission_manager · vlm_task_planner)이 정하고, coordinator(②)는 실행만 합니다. 팔 동작은 전부 MoveIt을 거칩니다.

2. 미션 단계 — mission_manager

ros2 topic pub --once /cmd/mission std_msgs/msg/String "{data: start}"로 시작합니다. 관측(바코드, 신호) 실패와 복귀 실패만 ERROR로 멈추고, 나머지는 퍽·장소 단위로 결과를 남기고 계속합니다.

flowchart TB
  IDLE["IDLE"] -->|"/cmd/mission start"| GO["GO_OBSERVE<br/>pose scan · 바코드 보는 자리로"]
  GO --> BC["BARCODE<br/>이번에 본 바코드 (/tracked_objects barcode · /mission/qr)"]
  BC --> RD["READ<br/>관측 자리(−X)에서 12회 점멸"]
  RD --> SV["SURVEY<br/>시작 박스 6곳: inspect → pick → load 칸<br/>→ 12개 한 번에 할당"]
  SV --> BD["BUILD<br/>퍽마다: 장소 앞 → unload 칸 → place 주사위 칸<br/>→ 내려다보고 확인 · 벗어나면 다시"]
  BD --> VF["VERIFY<br/>장소마다 새로 본 퍽만으로 칸 판정 · 12개 중복·누락"]
  VF --> RT["RETURN<br/>출발 구역 · 차체 전체가 구역 안 · 3초 정지"]

  BC -. 실패 .-> ERR
  RD -. "오류 사이클 이어짐 · 시간 초과" .-> ERR
  SV -. "할당 불가" .-> RT
  RT -. 실패 .-> ERR

3. 신호 판정 (READ)

signal_decoder가 12회 점멸을 세어 냅니다. READ가 시작된 뒤에 끝난 사이클만 봅니다. /mission/signal은 같은 답이면 다시 나오지 않아서, /mission/signal_status의 ok도 확정으로 봅니다.

  ST["/mission/signal_status<br/>(사이클마다)"] --> D{"ok?"}
  SG["/mission/signal<br/>(새 답 확정 때)"] --> D
  D -->|"예 (두 사이클 같은 답)"| ACC["확정<br/>R·Y·G 횟수 + 바코드<br/>→ L1·L2·L3 배정"]
  D -->|"error = unconfirmed"| W["기다림<br/>(다음 사이클)"]
  D -->|"count · unknown · range"| C{"이어진 오류<br/>≥ 2번?"}
  C -->|"아니오"| W
  C -->|"예"| STOP["ERROR · 안전 정지<br/>(추정 금지)"]
  W -->|"150초 넘음"| STOP

경유점 — 표(A) vs 직접 계산(B), 둘 다 만들어 비교

강화학습 정책(right_*.onnx)은 경유점을 만들지 않고, 기본 경유점에 관절 보정(±0.1 rad)만 더합니다. 그래서 기본 경유점을 표로 받든(A) 직접 계산하든(B) 보정은 같은 자리에서 더해집니다.

flowchart TB
  IN["누운 퍽 위치 · 축 방향 · 모양<br/>(/tracked_objects)"] --> SEL{"stand_waypoints"}
  SEL -->|"table (A)"| TA["팀원 표<br/>모양 × 방향 5° × 옆 위치 3곳<br/>관절 경유점 + 보간"]
  SEL -->|"ik (B)"| TB["직접 계산<br/>팀원 기하(호 7.5°마다) +<br/>손 아래 향하는 5축 해석 IK"]
  TA --> EX["관절 경유점 → 한 궤적<br/>MoveIt ExecuteTrajectory"]
  TB --> EX
  EX --> RL["rl_arm_correction<br/>(강화학습 보정 Δ ±0.1 rad — 전달 방식 정해지면 A·B 공통)"]
A. 표B. 직접 계산
경유점팀원이 isaac-lab에서 미리 푼 관절 경유점 (퍽 모양 × 축 방향 5° × 옆 위치 3곳), 사이는 보간팀원 기하 그대로 (먼 끝 쥐기 → 모서리 축 호 7.5°마다 → 120° → 90° → 놓기) + 손 아래 향하는 5축 해석 IK
장점학습 때와 같은 궤적 → 보정 정책이 잘 맞음표 없이 어떤 퍽 위치에도 대응
필요한 것표 형식을 정하고 팀원이 그 형식으로 내보내기해석 IK 구현 (MoveIt IK는 위치만 맞춰 손 방향을 보장 못 함 — rotation_scale: 0)
상태형식 정리 · 표 대기만드는 중
실기에서 "가볍게 쥐기"(0.4N)는 그리퍼 힘 명령(펌웨어)이 생긴 뒤 가능합니다. Isaac은 팀원 우회 방식으로 됩니다.

8. 정한 것 (11-02)

항목결정
팔 동작 경로전부 MoveIt (move_group → ExecuteTrajectory → JTC → rl_arm_correction). 예외: 기동 initial_pose · manual_control
흐름 조립계획 쪽이 단계를 다 적어 보냄 (load·unload 안 carry 경유만 skill 안)
놓은 뒤 자세place는 그 자리에서 끝, 주행 전에 부르는 쪽이 pose stow
reset_sag팔 skill마다 시작할 때 한 번
세우기 이름stand · stand_pick
세우기 경유점표(A)와 직접 계산(B) 둘 다 — stand_waypoints: table | ik로 골라 비교
잡기 판정 기준남음 — 지금 위치 3mm · 전류 0.25A (실측: 원기둥 3.85mm · 직육면체 5.11mm, 쥐는 전류 0.3~0.4A)
